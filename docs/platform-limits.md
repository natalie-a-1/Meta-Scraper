# Platform limits and Apple Pay

Research checked September 8, 2026. Recheck before launch because the native checkout APIs and commercial eligibility are evolving.

The closest supported implementation of the requested experience is **ChatGPT’s native payment sheet**, with Apple Pay as a supported method. OpenAI’s [checkout reference](https://developers.openai.com/plugins/build/monetization) documents `window.openai.requestCheckout`, the payment-provider schema and the `complete_checkout` callback. Apple Pay is explicitly present in the example’s supported payment methods. This repository uses those fields; it does not fabricate an Apple Wallet sheet.

Native checkout remains a **private beta for selected marketplaces**. Setting a configuration flag or adding Apple’s JavaScript cannot unlock it. OpenAI’s [UI guide](https://developers.openai.com/plugins/build/chatgpt-ui#use-the-chatgpt-payment-sheet) confirms this limitation. Current general commerce approval covers **physical goods**; digital app credits, subscriptions and service payments require separate explicit enablement. This is a platform constraint on the original universal app-payments concept, not an implemented digital-goods capability.

The [submission guidelines](https://developers.openai.com/plugins/app-guidelines#checkout) prohibit embedding other third-party checkout solutions in plugin UI. The checkout and UI guides also describe using payment methods already saved with a merchant, while the general submission wording still calls external checkout the default. We did not use the saved-method flow to sidestep that ambiguity or the user’s seamless setup goal. The chosen implementation is the explicitly documented native flow.

Apple’s [web payment APIs](https://developer.apple.com/documentation/applepayontheweb) require Apple’s supported browser/merchant integration and do not establish compatibility with ChatGPT’s controlled iframe. The requesting app cannot control ChatGPT’s parent frame, permissions, native entitlements or Wallet. No direct `ApplePaySession`, embedded PSP frame, fake Apple Pay brand button, Face ID animation or double-click-side-button instruction is used. When an enabled host displays genuine Apple Pay, Apple and the host handle authentication.

The request API enables **participating merchants** to integrate. There is no documented universal ability for this app to intercept payment requests from every installed plugin. Both integrations must be available to the host, and the requesting service must explicitly implement the handoff and trusted account mapping. OpenAI adds host-owned merchant/connector context to the native sheet; marketplace branding and per-seller settlement must be validated with OpenAI and the PSP rather than overwritten in client code.

Stripe’s old app-monetization documentation link now redirects to [MPP-based MCP monetization](https://docs.stripe.com/agentic-commerce/monetize-mcp). That is a different agent-wallet payment flow and does not demonstrate native Apple Pay in ChatGPT. This implementation instead uses the [documented seller shared-payment-token API](https://docs.stripe.com/agentic-commerce/concepts/shared-payment-tokens?agent-seller=seller) behind OpenAI’s `complete_checkout` contract. The exact native host/Stripe token envelope still needs partner validation.

The code can be reviewed and the local demo can be run now. Public launch depends on OpenAI/PSP access, merchant and identity setup, the enabled-host integration test, and normal merchant fulfillment operations. The PR does not claim those external prerequisites have been completed.
